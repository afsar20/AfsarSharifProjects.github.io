SPY Implied-Volatility Surface

A small end-to-end market-data application: resolve the option chain, request model implied volatility, capture timestamped snapshots and recreate the surface offline.

The build

From a live chain to a repeatable research snapshot

The application connects to a locally running Interactive Brokers Trader Workstation or Gateway session. It resolves the SPY underlying contract, retrieves the SMART option-chain definition and selects the next four expiries with up to nine strikes within roughly 6% of spot.

To focus on the more liquid out-of-the-money side, the grid requests puts below spot and calls at or above spot. IBKR model implied volatility is collected asynchronously, while contract-level events prevent missing definitions from blocking the entire chain.

Why save the snapshot?

Separating collection from analysis makes the result reproducible. A reviewer can inspect the exact inputs, rerun the plot without a live market connection and distinguish a data issue from a visualisation issue.

Data flow

A small event-driven pipeline

Interactive Brokers callbacks arrive asynchronously, so the application keeps contract metadata, request IDs and observations separate before joining them for the surface.

Surface interpretation

The sample shows a pronounced short-dated smile with higher implied volatility away from spot. The chart is useful for inspecting shape and data coverage, not for pricing or relative-value trading.

Operational controls

Timeouts, contract-resolution events, data-mode reporting and a saved-snapshot fallback make failure states visible and keep the desktop display from being the only record of the result.

Limits

What would change in a production surface

This is a visual research tool, not an arbitrage-free calibration. It uses strike rather than forward moneyness, does not fit a parametric model, and does not explicitly adjust for rates or dividends. The saved example is short-dated and sparse; edge values are interpolated where the final strike is unavailable for an expiry.

A production version would add quote-quality filters, bid/ask-aware IVs, forward normalisation, no-arbitrage checks, a calibrated model such as SVI, and monitoring for stale or crossed markets.

Run requirements

  • Interactive Brokers Trader Workstation or IB Gateway running locally.
  • API connections enabled and the appropriate US equity and options market-data subscriptions.
  • Python packages listed in the repository's requirements file.
  • No broker username, password or API credential is stored in the project.
